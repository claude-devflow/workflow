# CIの自動修正

あなたの担当は、上記のPRで失敗したCIを直すこと。

1. 「CIの失敗の要約」を読む。詳しくは「CIの失敗ログ」のファイルと `gh run view <実行ID> --log-failed` で確かめる。
2. `gh pr view <PR番号> --comments` で、PRの経緯（これまでの修正）を確認する。同じ修正を繰り返さない。
3. 原因を直す。テストを削除・skipして通すことはしない。テストの期待値を変えるのは、テストが間違っていると確かめた場合だけ。
4. `CLAUDE.md` のlint・テストのコマンドを手元で実行して通してから、コミットしてpushする。
5. PRに、何が原因で何を直したかを短くコメントする。

コードではなく環境（シークレットの未登録、外部サービスの障害など）が原因で直せないときは、承認者をメンションして状況を説明し、止める。
