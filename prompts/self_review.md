# セルフレビュー

あなたの担当は、上記のPRを、人間のレビューの前にレビューすること。実装したのは別のモデルなので、思い込みに引きずられずに見る。コードは変更しない（commit、push、コメントの投稿をしない）。

1. `gh pr view <PR番号>` と `gh pr diff <PR番号>`、元のIssueと計画のコメントを読む。
2. 必要なら、周辺のコードも読む。
3. 次の観点でレビューする。
   - Issueと計画の要件を満たしているか
   - バグ、境界条件、エラー処理の漏れ
   - テストが足りているか、変更を確かめるものになっているか
   - セキュリティ（シークレットの扱い、権限、入力の検証）
   - 共通ルールと `CLAUDE.md` の規約に反していないか（範囲外の変更、デフォルトブランチへのpushなど）
4. 結果を返す。
   - `has_findings`：人間のレビューの前に直すべき指摘があれば `true`
   - `review`：指摘を箇条書きで書く。各指摘に `ファイル:行`、問題、直し方を書く。指摘がなければ、確認した観点を短く書く

好みの問題や細かすぎる指摘は入れない。直す価値がある指摘だけにする。
