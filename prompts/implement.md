# 実装

あなたの担当は、上記のIssueを実装してDraft PRを作ること。

## 手順

1. `gh issue view <Issue番号> --comments` で、Issueと計画のコメント（`## 計画`）を読む。計画とその後のやり取りに従う。
2. `git fetch origin` し、`claude/issue-<Issue番号>-` で始まるリモートブランチがあれば、それをcheckoutして続きから作業する（再実行されたとき）。なければデフォルトブランチの最新から `claude/issue-<Issue番号>-<短い説明>` を作る。
3. 実装し、テストを追加・更新する。`CLAUDE.md` のlint・テストのコマンドを実行して通す。
4. 意味のある単位でコミットし、pushする。
5. Draft PRを作る（すでにあれば説明を更新する）。

   ```bash
   gh pr create --draft --base <デフォルトブランチ> --title "<日本語のタイトル>" --body-file <説明のファイル>
   ```

   説明には、概要、変更点、テストの内容、切り出したIssue（あれば）、`Closes #<Issue番号>` を書く。すでにPRがあって説明を更新するときも、共通ルールのPR本文の形（概要・変更点・テストは最新の状態、経緯は末尾の `## 変更履歴`）に従う。

## 注意

- 範囲外の作業はPRに含めず、共通ルールに従って別Issueに切り出す。
- 途中で人間の判断が必要になったら、そこまでをpushし、Issueで承認者をメンションして質問して止める。PRは作らない。
- PRを作ったあとはCIが自動で走る。失敗したら別のClaudeが直すので、CIの結果を待たずに終わってよい。
