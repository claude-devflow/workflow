# flaky testの原因の分析と起票

CIが1回失敗し、再実行で通った。あなたの担当は、1回目の失敗の原因を分析し、起票すること。コードは変更しない。

1. 「CIの失敗ログ」のファイル（1回目の失敗のログ）を読む。
2. 失敗したテストのコードを読む。
3. 分析を書いたファイルを作る。症状、推定される原因（タイミング、順序依存、外部依存、乱数など）、直し方の案を短く書く。
4. 次のコマンドで起票する。同じテストのIssueが開いていれば、スクリプトが発生回数を追記する。

   ```bash
   bash "$DEVFLOW_DIR/scripts/flaky-issue.sh" "<テスト名>" <分析のファイル>
   ```

   テスト名は、失敗したテストを一意に表す名前にする。ログに出ている形のまま、ファイルのパスとテスト名で書く（例：`src/user.test.ts > ユーザー登録 > 重複したメールを拒否する`）。同じテストなら毎回同じ文字列になるようにする。失敗したのがテストではない場合（依存のインストールの失敗など）は、失敗したジョブとステップの名前を書く。
